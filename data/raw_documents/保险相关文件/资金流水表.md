| 资金流水表 | 我方IP地址 | 1、填报人身保险公司完成该笔资金交易所使用终端的IP地址，指点分十进制格式表示的IPV4或IPV6地址。 | 1、网银交易报送发送交易指令所使用终端的IP地址，现金收付交易如不适用，可据实报送不适用。<br>2、对于当前系统部署存在多个ip地址，且非固定ip，会存在不同报送时点IP不一致的情况，建议据实报送每笔资金流水对应的IP地址。<br>3、对于部分业务（例如投资业务）是公司以邮件方式提交付款指令至银行，由银行在系统内进行资金划转操作的，公司不掌握银行的IP,也没法记录每个指令由哪台电脑发送的情况，建议报送邮件发送终端所对应的IP地址信息，若按照规范要求报送数据存在困难，建议向监管部门报备说明，并同步说明可按要求报送数据的计划与时间安排。在可按要求报送数据前，建议报送“未记录”。<br>4、关于IP地址与MAC地址的报送要求，补充以下场景描述与处理建议：<br>问题1：批量收付等交易由业务人员在业务系统确认收付费信息后，直接推送至收付费系统，收付费系统与资金系统对接后，直接向银行发送指令，并由银行完成收付动作。从“收付费系统-资金系统-银行收付”这一过程，完全由系统自动化进行，不涉及人工操作（除部分情况下，如收付账户存在交易限额时，可能涉及人工处理）。<br>处理建议1：上述场景下，若不存在发行指令的终端，建议据实报送服务器地址。但对于网银转账、涉及人工操作等存在发送指令终端的场景，应据实报送相关终端的IP、MAC地址。<br>问题2：基于第1点所描述场景，还存在以下问题：部分公司出于资源负载均衡考虑，设置多台服务器共同发送指令，致使一笔资金流水涉及多个地址。例如，假设某笔批量付款业务包含100笔交易明细，共计100元，且这100元由代付银行一笔划走。部分公司设置了4台服务器共同发送指令，即每台服务器发送25笔交易明细，此时，这笔100元的资金流水将存在4个IP地址与MAC地址。<br>处理建议2：建议以英文半角分号分隔，据实报送4个地址。<br>问题3：收款场景或不涉及保险公司端操作。<br>处理建议3：收款场景下，若不涉及单独的收款确认，相关地址建议报送“不适用”。若涉及单独的收款确认，按照确认方式进一步区分：手工回盘的，建议报送手工确认电脑的IP、MAC地址；系统回盘的，建议报送相关服务器的IP、MAC地址。 |

| 资金流水表 | 对方账号 | 1、填报该笔资金交易的对方账号。特殊情况说明如下：（1）对于部分自动结算类交易（如结算费、利息等），若银行对账单未提供对方账户信息，填报“不适用”。（2）部分银行流水（如现金、现金缴款单对应场景）若无法报送该信息，报送“不适用”。（3）对于投资资金托管账户与证券交易资金结算账户间的流水，此处填报资金结算账户的账号。（4）对于与本机构第三方支付账户（或数字货币钱包）间的提现与充值交易，此处填报第三方支付机构（或数字货币钱包开立机构）实际收付该笔资金的账户账号（如第三方支付机构的备付金账户）。对于上述特殊情况，应在“备注”中予以说明。 |  |
| 资金流水表 | 对方账户户名 | 1、填报与“对方账号”相匹配的账户名称。若为自然人客户，隐私，人身保险公司变形。 | 1、公司按照合理规则识别个人账户信息并作脱敏处理。<br>2、对于银保通渠道业务，若由代销银行一笔打款给保险公司，应报送银行打款所使用的账号。若银行未提供其打款账号，建议按照默认值“未记录”报送。 |
| 资金流水表 | 对方账户开立机构名称 | 1、填报与“对方账号”相匹配的账户开立机构名称。若部分银行仅提供对方账号、对方账户户名，未提供对方账户开立机构名称，报送“未记录”。 |  |
| 资金流水表 | 货币代码 | 1、填报该笔资金交易流水所使用货币对应的代码。例如：CNY、EUR、JPY等。<br>2、参照《业务代码表》“币种代码”，编号CD000009。 |  |
| 资金流水表 | 交易金额 | 1、填报该笔资金流水对应的金额。 |  |
| 资金流水表 | 资金方向 | 1、填报该笔流水的资金交易方向。其中，“提现”与“充值”仅适用于人身保险公司第三方支付账户（或数字货币钱包）与其关联银行账户间的资金划转交易。“提现”表示资金自第三方支付账户（或数字货币钱包）转入其关联银行账户；“充值”表示资金自银行账户转入相关第三方支付账户（或数字货币钱包）。<br>2、枚举值：收款；付款；提现；充值。 | 1、对于公司与银行合作的聚合收款和二维码收款业务，与聚合商户号所绑定银行账户的资金流水，“资金方向”可按“收款”或“付款”报送。<br>2、给第三方支付机构支付的手续费，资金方向可按付款报送。 |

| 资金流水表 | 交易时间 | 1、银行账户下该笔资金流水的产生时间，以各公司系统记录的时间为准。 | 1、优先以银行反馈的交易时间信息为准报送；若银行未反馈相关信息，建议以各公司内部系统记录的信息报送；若两者均无，建议报送默认值000000，并进行报备说明。 |

| 资金流水表 | 记账凭证号 | 1、直接反映该笔流水实收付信息的记账凭证号。说明如下：（1）应填报确认收付该笔流水直接相关的凭证信息，而非业务凭证信息。（2）若存在“银收企未收”或“银付企未付”等情况，该笔流水仍应在产生当期报送，“记账凭证号”可暂时填报“未生成”，并在相关凭证产生后予以更新。（3）若存在“企收银未收”或“企付银未付”等情况，与该笔流水相关的记账凭证应在凭证生成当期报送《财务凭证信息表》，相关资金流水则可待产生后报送《资金流水表》。（4）对于投资业务中存在的净额结算、轧差结算（如DVP结算模式）等场景，若无法实现资金流水与记账凭证间的关联，报送“000000”。 | 1、对于资金流水与记账凭证号一对多的情况，建议根据财务记账情况，据实以英文半角分号分隔，报送多个记账凭证号。<br>2、对于部分业务（例如投资业务）没有通过系统进行资金处理，未记录资金流水，对账也是通过线下人工核对完成的，无法将资金流水与记账凭证号进行关联的情况，建议按照“未记录”报送，并按规范印发通知要求，向监管部门报备原因及可按要求报送数据的工作计划。<br>3、对于跨月调整/冲销的场景，由于“会计期间”也为该表主键，因此原记账凭证与更新记账凭证可分别报送一条资金流水数据（即次月冲销时可更新报送一条数据）。但为便利监管应用数据，建议在更新记账凭证所对应的数据“备注”项中简要说明有关情况。<br>4、对于原资金流水表记账凭证号报送错误（在次月发现错误），同时该笔资金流水在报送当月未记账，实际记账日期跨度较大的情况，在发现问题的当月《资金流水表》中对于该笔资金流水的记账凭证号更新为“未生成”，在实际记账的当月《资金流水表》中对该笔资金流水记账凭证号更新报送为准确记账凭照号。<br>5、对于第三方账户存现、提现有关资金流水，可按存现、提现的凭证报送。 |
